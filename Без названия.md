# Aider + DeepSeek + GPT: полная инструкция

## 0. Схема работы

| Роль | Модель | Когда |
|---|---|---|
| Основная (правки кода) | `deepseek/deepseek-chat` | всегда по умолчанию |
| Сложная отладка | `deepseek/deepseek-reasoner` | точечно, через `/model` |
| Критик (проверка) | GPT (`gpt-4o-mini`, для важного `gpt-4o`) | только в режиме `/ask`, без правок |

Принцип: **дешёвая модель пишет, дорогая только проверяет, и только когда вы попросили.**

## 2. Общие настройки (для всех проектов)

### `C:\Users\Administrator\.aider.conf.yml`

``` yaml
model: deepseek/deepseek-chat
weak-model: deepseek/deepseek-chat
cache-prompts: true
map-tokens: 1024
auto-commits: true
analytics-disable: true
auto-test: false
read: [C:/Users/Administrator/.aider/CONVENTIONS.md]
alias:
  - "ds:deepseek/deepseek-chat"
  - "r1:deepseek/deepseek-reasoner"
  - "crit:gpt-4o-mini"
  - "crit+:gpt-4o"

```

Алиасы позволяют переключаться командой `/model crit`. Имя пользователя замените на своё, если оно другое.

### `C:\Users\Administrator\.aider\CONVENTIONS.md`

``` markdown
- Language of code/comments: English. Answer to user: Russian.
- Minimal diffs. No refactors, renames, new dependencies, or reformatting unless asked.
- Match the existing style, naming, and libraries of the project.
- Read the surrounding code before changing behavior; don't guess APIs. If unsure, say so.
- Every non-trivial logic change: add or update a test. Never delete tests to make them pass.
- Handle errors at boundaries (I/O, network, user input); no silent except/catch.
- Never print, log, or commit secrets. Don't touch .env, keys, or credentials files.
- Small files and functions. If a file exceeds ~300 lines, suggest splitting first.
- After a change: one line on what changed and how to verify it.

```

### Проверка имён моделей

Названия моделей у провайдеров меняются, поэтому сверяйтесь с актуальным списком:

``` bash
aider --list-models deepseek
aider --list-models gpt

```

Если какое-то имя из алиасов не найдено, замените его на существующее из списка.

## 3. Подготовка проекта (один раз)

1. `git init` и первый коммит. Без git Aider работает хуже, и нет отката.
2. `.aiderignore` в корне:

``` text
docs/
__pycache__/
node_modules/
.venv/
*.lock
test_run.txt
README.md

```

3. `ARCHITECTURE.md` до 40 строк: цель, стек, файлы и их роль, как запускать, инварианты.
4. Проектный `.aider.conf.yml`:

``` yaml
read: [ARCHITECTURE.md, C:/Users/Administrator/.aider/CONVENTIONS.md]
test-cmd: python -m pytest -q

```

5. Запустите `aider`, затем `/tokens` и убедитесь, что оба файла из `read` в списке.
6. Секреты (`config.json` с паролем) в контекст не добавлять. Если файл в git, добавьте его в `.gitignore` и храните `config.example.json`.

## 4. Режимы чата

| Команда | Что делает | Файлы правит |
|---|---|---|
| `/code` | обычный режим правок | да |
| `/ask вопрос` | вопрос или ревью | нет |
| `/architect` | планировщик + исполнитель (2 вызова) | да |
| `/chat-mode` | показать или сменить режим | нет |

Режим `/architect` не включайте по умолчанию: он вдвое дороже.

---

## 5. Управление контекстом

| Команда | Назначение |
|---|---|
| `/add файл` | файл можно править, уходит в модель целиком |
| `/read-only файл` | файл только для чтения (справка, тесты, API) |
| `/drop файл` | убрать файл из контекста |
| `/drop` | убрать все файлы |
| `/clear` | очистить историю чата |
| `/reset` | сбросить и файлы, и историю |
| `/tokens` | сколько токенов занимает контекст |
| `/map` | показать карту репозитория |

Правила:
- Добавляйте только файлы, нужные для текущей задачи.
- Большие файлы (больше ~300 строк) добавляйте в `/read-only` или не добавляйте совсем.
- Карта репозитория показывает **только имена функций и классов**. Чтобы проверить логику, нужен файл целиком.
- После завершения задачи: `/drop` и `/clear`.

## 6. Работа с DeepSeek

### Основной режим
``` text
/add app.py
Добавь проверку max_step_mm в эндпоинт /api/move. Тест тоже.

```

Хорошие запросы:
- одна небольшая задача за раз;
- указан файл или функция;
- указан критерий результата («тест проходит», «возвращает 400»).

Плохие запросы: «улучши проект», «сделай красиво», «исправь всё».

### Reasoner (сложная отладка)

``` text
/model r1
Тест test_move_lost_reply падает. Найди причину.
/model ds

```

- Reasoner тратит много токенов на рассуждения. Включайте его на один запрос и возвращайтесь.
- Для рутинных правок он не нужен.

### Кэш
- Системный префикс и файлы из `read` кэшируются, поэтому они остаются неизменными.
- В строке под ответом видно `Tokens: ... sent`, `Cost: ...`. Следите за ней.
- При смене модели кэш другой модели не используется. Не переключайтесь часто.

## 7. Работа с GPT как с критиком

Критик нужен для проверки, а не для написания кода.

``` text
/model crit
/ask Проверь последнее изменение (git diff HEAD~1): баги, регрессии, граничные случаи, нарушенные инварианты из ARCHITECTURE.md. Только список, макс. 5 пунктов.
/model ds

```

Если в `/ask` нужен код целиком, добавьте его через `/read-only` до переключения модели.

Какую модель брать:

| Ситуация | Модель |
|---|---|
| обычная проверка | `crit` (`gpt-4o-mini`) |
| код, двигающий механику, безопасность, сложная логика | `crit+` (`gpt-4o`) |

Правила:
- Критика всегда в `/ask`, а не в `/code`, иначе GPT начнёт переписывать файлы.
- Если GPT нашёл «баг», проверьте его сами или тестом, прежде чем править. Критик тоже ошибается.
- Не отправляйте GPT файлы с секретами.

Альтернатива без смены модели в Aider: вторым окном запустить `chat.py` и выполнить `/diff` (см. инструкцию по консольному ассистенту).

## 8. Режим architect (редко)

Нужен для крупных задач с несколькими файлами:

``` text
/architect Вынеси валидацию из app.py в validation.py, поведение не менять.

```

Можно задать связку: планирует reasoner, пишет chat.

``` bash
aider --architect --model deepseek/deepseek-reasoner --editor-model deepseek/deepseek-chat

```

Это в 2-3 раза дороже обычной правки. Используйте для рефакторингов, когда тесты зелёные.

## 9. Тесты, откат, коммиты

| Команда | Назначение |
|---|---|
| `/test` | запустить `test-cmd` |
| `/run команда` | выполнить команду, вывод можно отправить модели |
| `/diff` | показать последнее изменение |
| `/undo` | откатить последний коммит Aider |
| `/commit` | закоммитить ваши ручные правки |
| `/git команда` | выполнить git-команду |

Порядок правки:
1. Убедитесь, что `/test` зелёный (базовая линия).
2. Поставьте задачу.
3. `/diff` и прочитайте изменения.
4. `/test`.
5. Если плохо, `/undo`.
6. Для важного: критик (раздел 7).

`auto-test` оставляйте выключенным: каждый упавший тест запускает новый платный цикл правок.

## 11. Контроль расхода

| Действие | Эффект |
|---|---|
| `/tokens` перед большой задачей | видно стоимость контекста |
| `/read-only` вместо `/add` для справочных файлов | модель не пытается их править |
| `/clear` между задачами | история не копится |
| `/ask` вместо `/code`, если нужен только ответ | меньше выходных токенов |
| reasoner и GPT-4o только точечно | дорогие модели не работают по умолчанию |
| файлы до ~300 строк | Aider отправляет файл целиком |
| не запускать `/architect` и `auto-test` без нужды | нет двойных вызовов и циклов |

Ориентиры из практики: запрос с картой и 3 файлами около 7k токенов, ~$0.002 на DeepSeek. Точные цены смотрите в личных кабинетах провайдеров.

## 12. Безопасность проекта `duet2-alignment`

Приложение двигает физические оси, поэтому:

- Инварианты из `ARCHITECTURE.md` (раздел SAFETY INVARIANTS) не ослаблять без явного решения.
- Любую правку `app.py` и `duet_client.py`, касающуюся движения, проверять критиком `crit+` и тестами.
- `config.json` не добавлять в чат (там IP и пароль платы).
- Тесты и отладка только с Mock, пока не убедились, что в `config.json` не указана реальная плата.
- Первый запуск после правок на реальной плате: минимальный `max_step_mm`.

## 13. Частые проблемы

| Симптом | Причина и решение |
|---|---|
| `Repo-map can't include ... deleted from the file system` | файл есть в git, но удалён с диска: `git rm --cached файл` или `git restore файл` |
| модель просит добавить файлы | карта не содержит тел функций: `/read-only файл` |
| `AuthenticationError` | ключ не задан в текущем окне: перезапустить терминал, проверить `echo $env:...` |
| `model not found` | устаревшее имя: `aider --list-models ...` |
| не подхватился `ARCHITECTURE.md` | `/tokens`: проверить, что файл в списке `read` проектного конфига |
| Aider правит лишнее | сузить задачу, указать файл и функцию, добавить «не менять остальное» |
| дорого | `/tokens`, `/drop`, `/clear`, проверить, не включён ли reasoner или architect |

/read-only f    только читать         /architect    план + исполнение

## 15. Что я не проверял
- Точные имена моделей OpenAI и DeepSeek в вашем аккаунте на текущий момент.
- Актуальные цены и лимиты.
- Совмещение списков `read` в общем и проектном конфигах (проверка через `/tokens`).
- Точный набор команд в вашей версии Aider: `/help` покажет доступные.
